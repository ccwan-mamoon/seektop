# Seek.li 原生邮箱接入

接口依据：2026-11-16 从官方 https://seek.li/api/openapi.json 读取的 OpenAPI 3.0 规范。
服务根地址：https://seek.li/openapi/v1。认证为 Authorization: Bearer sk_live_...。

## 已实现

原生三栏邮箱支持邮箱下拉、分页与搜索、邮件详情、已读与星标、移动文件夹、标签管理、删除、原文导出及附件列表/下载。写信使用 Markdown 工具条与预览，提交转义后的 HTML，支持抄送、密送及发送确认。

邮箱管理与邮件管理页面提供：邮箱创建/地址检查/设置/释放与恢复；联系人、文件夹、标签、收信规则和签名的增删改查；未读邮件游标分页、邮件计数、存储和配额查询、独立附件上传。修改操作需确认，失败不自动重试。规则条件和动作的内部结构未在公开规范定义，当前提供高级 JSON 输入，不猜测规则语义。

桌面网络使用固定域名和方法白名单、禁止重定向、无 Cookie 请求和响应大小限制；API Key 通过 Electron safeStorage 加密保存。异常与诊断不包含密钥或邮件正文。

权限由服务端按 API Key scopes 控制；权限不足会显示请求状态，不扩大权限或绕过官方 API。

## 验证与限制

JVM 和 Node 测试使用本地夹具；实际账号详情读取曾验证成功。管理写入和发送未使用真实账号自动执行。HTML 正文当前安全转为文本，不执行邮件脚本或加载远程图片。

公开 API 未提供账户管理、邮箱共享/转让、知识林、操作日志、拦截邮件或清理任务接口，这些站点页面不能仅凭截图实现。未读系统通知、草稿和安全 HTML 排版尚未实现。

## 详情与编辑修正（2026-11-16）

实际成功详情响应是 `data.mail`（同层还有 `tags`），与公开规范直接返回 `data: Mail` 的形状不同。读取器兼容两种包裹方式，并校验返回邮件 ID。客户端实际请求已确认 HTTP 200 并正常显示正文；诊断文件只存字段类型，不含密钥、主题、地址或正文。

写信支持原生 Markdown 工具条和预览；通过同一解析树生成经过转义的 HTML，同时提交 bodyText 和 bodyHtml。HTML 输出拒绝非 http/https/mailto 的链接方案。

用户已确认：公开 API 没有可靠附件发送引用和定时发送字段时，这两项不接入。当前不提供对应按钮。

## 创建校验与错误说明

创建使用前缀输入和 nodeseek.org/seek.li 后缀下拉。输入停止 500 ms 后调用官方 POST /mailboxes/check?address=...，地址可用才允许创建；更换输入或后缀会立即失效原检查结果。

管理错误显示官方 error.code 和 error.message（限长并隐藏 API Key），不再将写入错误统一称作邮件加载失败。响应原文不会写入日志。释放请求仍遵循公开文档的 DELETE /mailboxes/{id}；服务端拒绝的具体原因需以错误说明为准。

## 邮箱外观与刷新方式

邮箱独立使用蓝色操作色和高对比未读徽标；正文使用 onSurface 中性色，列表提供选中态。API Key 页面提供直达官方开发者配置页的链接。

使用定时拉取而非实时推送：默认 60 秒，可在邮箱设置中选择 30、60、120、300、600、1800、3600 秒并立即持久化。进入或切换邮箱时也会拉取，移除手动刷新按钮与刷新方式说明。定时任务在 ViewModel 生命周期内运行，断开账号、加载或发信时跳过；每次请求结束后再计时，不并发拉取，后台失败不弹窗。
